# Component Guidelines

Components should build a dense operator UI for repeated inspection and controlled actions, not a marketing page.

## Component Structure

- Export named React components.
- Keep screen composition close to the feature in `src/app/` until reuse is proven.
- Move reusable management-domain widgets to `src/components/management/`.
- Keep generated shadcn/ui primitives in `src/components/ui/` only when generated by the shadcn CLI.
- Use lucide-react icons for button and status affordances when an icon exists.
- Write user-facing labels, headings, empty states, notices, button copy, and
  confirmation copy in Simplified Chinese unless the text is a required
  technical token.

## shadcn/ui

- Initialize and update shadcn/ui through `bunx shadcn@latest ...` when possible.
- Do not hand-write generated files under `src/components/ui`.
- Wrap generated primitives in application/domain components when management-specific behavior or copy is needed.
- Current shadcn config is `components.json`, with `style: "new-york"`, `baseColor: "neutral"`, `iconLibrary: "lucide"`, and Tailwind CSS at `src/styles.css`.

## Props Conventions

- Type props with `interface` when the component has a named public contract.
- Use inline prop types only for small private helpers.
- Pass backend identifiers as logical service names (`service_name`), never Docker container names.
- Avoid props that accept arbitrary command strings, arbitrary shell text, arbitrary container names, or raw Docker API paths.
- Do not translate backend DTO field names, enum values, service names, command
  names, API paths, package metadata, or generated/tool output at the data
  boundary; translate only in display helpers when those values are shown to
  operators.

## Styling Patterns

- Use Tailwind CSS v4 utility classes.
- Use `cn` from `src/lib/utils.ts` for conditional class composition.
- Use 8px-or-smaller radius for cards and controls unless generated shadcn/ui output dictates otherwise.
- Keep tool and dashboard layouts compact, scannable, and stable across mobile and desktop.
- Do not use in-app explanatory feature text as a substitute for real controls or state.

## Accessibility

- Use semantic elements for tables, navigation, headers, buttons, and status groups.
- Icons that only decorate visible text must use `aria-hidden="true"`.
- Interactive controls must be buttons or links, not clickable divs.
- Preserve keyboard access for service selection, tabs, menus, and future command workflows.

## Management UI Safety

Components must not expose:

- Arbitrary shell command input.
- Docker API explorers or Docker exec.
- Container create/delete, image pull/build/push, Compose editing, or bind mount editing.
- Arbitrary container name input.
- Arbitrary command string input.
- Direct ROS CLI or backend bypass controls.
